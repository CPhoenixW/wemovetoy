# WEMOVE P1 后端基础架构计划

## 已确认范围

- 在 `backend/` 下搭建可运行的 NestJS + TypeScript 后端。
- 使用 Docker Compose 提供 PostgreSQL，并通过 Prisma 管理数据库迁移。
- 实现 `User`、密码认证、JWT 访问令牌，以及 `USER`、`DEALER`、`ADMIN` 三类角色守卫。
- 所有版本化接口使用 `/api/v1` 前缀，提供 Swagger、健康检查、参数校验、统一响应和全局异常处理。
- 提供种子账号、英文项目说明，以及中文开发文档和使用文档。
- P1 不实现商品、购物车、订单和经销商具体业务；仅保留清晰、稳定的模块边界与扩展位置。

## 验收标准

- Docker Desktop 可用时，执行 `docker compose up -d` 能启动 PostgreSQL。
- Prisma 能应用首个迁移，并写入三个角色的种子账号。
- 后端可构建和启动，`/api/v1/health` 与 `/api/docs` 可访问。
- 注册、登录、携带令牌访问 `/api/v1/auth/me` 均可运行。
- 未认证访问受保护接口返回 401；角色不符返回 403；后续业务模块可复用角色守卫。
- 团队成员可按照中文文档完成环境配置、迁移、种子数据、测试及模块扩展。

## 环境依据与约束

- 当前工作区只有需求文档，没有既有代码、仓库规范或可复用项目结构。
- 本机为 macOS arm64，已安装 Node `v26.0.0` 和 npm `11.12.1`；检查时 3000、5432 端口均未被占用。
- 当前终端未找到 Docker。可以创建并静态检查 Docker 配置，但容器、数据库、迁移和 HTTP 集成验证需要 Docker Desktop 安装并启动后才能完成。
- 未获授权执行远程推送、部署、生产数据迁移或 Git 提交。

## 架构方案

- `backend/src/common`：配置、统一响应拦截器、异常过滤器、请求 ID 中间件、角色装饰器、JWT 与角色守卫。
- `backend/src/prisma`：Prisma 单例服务和模块。
- `backend/src/users`：用户查询与安全用户信息映射。
- `backend/src/auth`：注册、登录、当前用户接口、bcrypt 密码处理和 JWT 策略。
- `backend/prisma`：数据模型、首个迁移和可重复执行的开发环境种子脚本。
- 根目录 Docker Compose 仅负责 PostgreSQL；开发时后端在宿主机运行，以便快速调试。
- 初期角色使用枚举。细粒度 RBAC、经销商企业成员关系、审计日志、MFA、刷新令牌 Cookie 和限流将作为明确的后续工作，而不是提前创建不完整表结构或半成品安全能力。

## 风险、数据影响与回滚

- 当前缺少 Docker，会阻塞数据库相关的运行时验证。
- 首个迁移只会创建本地开发数据库，不影响已有数据。
- 回滚方式为停止并删除指定的本地 Compose 数据卷；该操作不会被自动执行。
- 后续引入细粒度 RBAC 或经销商企业隔离时，需要新增迁移并重新评审安全设计。
