## 缺陷

### BUG-001 匿名商品接口暴露经销商价格（已关闭）

- 严重程度：高
- 影响模块：products / 权限 / 商业数据
- 证据：公开 `GET /api/v1/products` 与 `GET /api/v1/products/:slug` 使用 `toSafeProduct`，返回字段包含 `dealerPrice`。
- 实际：未登录用户可以获得经销商价。
- 期望：公开接口仅返回零售价；经销商价应由已认证的经销商接口或基于角色的安全映射返回。
- 建议负责人：成员 2，成员 1 review 权限与响应契约。

### BUG-002 匿名商品列表没有强制只显示 ACTIVE 商品（已关闭）

- 严重程度：高
- 影响模块：products / 官网
- 证据：`ProductsService.findAll` 默认过滤条件只有 `deletedAt: null`，`status` 完全取自匿名查询参数。
- 实际风险：草稿或归档商品可能出现在公开列表，匿名用户还可主动传入状态筛选。
- 期望：公开列表服务端强制 `status = ACTIVE`；后台列表使用独立的管理员接口。
- 建议负责人：成员 2，成员 1 review API 边界。

### BUG-003 不存在的 Variant 加购可能返回 500（已关闭）

- 严重程度：中
- 状态：2026-09-06 本机运行复现
- 影响模块：cart / 统一错误处理
- 证据：`CartService.addItem` 未先查询 Variant；向 `/api/v1/cart/items` 提交不存在的 `variantId` 实际返回 500。数据库外键失败为 Prisma `P2003`，当前异常过滤器只映射 `P2002` 和 `P2025`。
- 期望：不存在、下架或不可购买的 SKU 返回 404/400，而不是 500；错误响应仍包含 `request_id`。
- 建议负责人：成员 2 与成员 3协作，成员 1 review 异常映射。

### BUG-004 Prisma CLI 与根目录 `.env` 文档不一致（已关闭）

- 严重程度：中
- 影响模块：本地开发 / 新成员上手
- 复现：只创建根目录 `.env`，进入 `backend` 执行 `npm run prisma:migrate`。
- 实际：Prisma 6.19.3 报 `Environment variable not found: DATABASE_URL`。
- 临时绕过：本机创建已被 Git 忽略的 `backend/.env`，只配置 `DATABASE_URL`。
- 期望：脚本显式加载 `../.env`，或文档要求生成 `backend/.env`，避免每名成员重复踩坑。
- 建议负责人：成员 1。

### BUG-005 种子脚本重复执行用户 upsert（已关闭）

- 严重程度：低
- 影响模块：seed / 日志可读性
- 证据：`backend/prisma/seed.ts` 中 `seedUsers` 循环出现两次，运行时也打印两次 `Seeded 3 development users.`。
- 实际：数据库因 upsert 不会产生重复用户，但会重复计算/写入并制造误导日志。
- 期望：保留一次用户 upsert 与一次日志。
- 建议负责人：成员 1。

### BUG-006 SKU 控制器可能产生双重 API 前缀（已关闭）

- 严重程度：高
- 影响模块：products / 前后端联调
- 证据：应用已经通过 `app.setGlobalPrefix("api/v1")` 设置全局前缀，但 `VariantsController` 又声明 `@Controller("api/v1")`。
- 实际：2026-09-06 启动日志确认控制器注册为 `/api/v1/api/v1`；访问预期单前缀路由返回“Cannot GET”，双前缀路由进入认证守卫并返回 401。
- 期望：Controller 只声明 `variants`，最终路由为 `/api/v1/variants/:sku`、`/api/v1/variants/batch` 和 `/api/v1/variants/check-stock`。
- 建议负责人：成员 2，成员 1 review 全局路由。

### BUG-007 普通用户 SKU 响应仍包含 dealerPrice（已关闭）

- 严重程度：高
- 影响模块：products / 权限 / 商业数据
- 证据：`VariantsService` 虽会按角色选择 `price`，但返回 DTO 始终包含原始 `dealerPrice`。
- 实际：普通登录用户可能同时拿到零售价和经销商价。
- 期望：普通用户响应不包含经销商价；只有 `DEALER` / `ADMIN` 可获得该字段或经销商定价结果。
- 建议负责人：成员 2，成员 1 review 响应契约。

## 阻塞项（不是用测试绕过的缺陷）

### BLOCK-001 SKU 服务已存在，但缺少可用于联调的 Variant 数据入口（已解除）

- 最新提交已增加 SKU 查询、批量查询和库存检查服务。
- 当前种子仍只创建 Product，没有 Variant；后台 API 也没有创建 Variant 的契约。
- 影响：无法通过 API 完成“看商品 -> 选 SKU -> 加购物车”。
- 解除条件：成员 2 提供 Variant 种子或管理 API，并修正 SKU 路由与角色价格字段。

### BLOCK-002 购物车仍使用零价格占位（已解除）

- `CartService.resolveUnitPrice` 固定返回 0，未注入新增的 `VariantsService`，未校验库存或 SKU 状态。
- 影响：即使手工插入 Variant，订单金额也不可信。
- 解除条件：成员 2/3 完成服务端价格和库存接口接入。

### BLOCK-003 订单快照仍为占位（已解除）

- `OrdersService` 将商品名称保存为 `Variant #<id>`，`variantName` 为 null，且未再次校验库存。
- 影响：订单历史不能满足真实商品/SKU/价格快照验收。
- 解除条件：成员 3 接入商品服务并补充库存、金额和快照测试。

### BLOCK-004 前端仍是页面骨架（API 前置阻塞已解除）

- 当前 Next.js 构建只有 `/`、`/login`、`/products` 等静态骨架。
- 影响：不能完成浏览器端“注册登录 -> 看商品 -> 加购 -> 下单”验收。
- 解除条件：成员 4/5 合入真实 API 页面后，成员 6 增加浏览器 E2E。
