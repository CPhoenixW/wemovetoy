# P2.0 展示与首页配置契约

## 1. 目的与范围

本文是 P2.1 官网展示迭代的接口和权限契约，供成员 2、4、5 实现与联调，成员 1 负责审查，成员 6 负责验收。

本轮只支持官网展示所需的有限首页配置和商品公开数据，不建设通用 CMS。真实支付、完整 Dealer Portal、文章/FAQ/下载中心、全站搜索和多语言不属于本契约。

接口统一使用 `/api/v1` 前缀。Nest 的全局前缀已经负责版本前缀，Controller 不得再次写入 `api/v1`。

## 2. 角色与数据边界

| 调用方 | 可访问内容 | 禁止内容 |
| --- | --- | --- |
| `PUBLIC` | 已发布首页、已发布商品的公开字段 | 草稿/归档内容、Dealer 价格、库存明细、后台字段 |
| `USER` | PUBLIC 内容；可使用现有购物车和订单接口 | Admin 配置、Dealer 价格和 Dealer 管理数据 |
| `DEALER` | PUBLIC 内容；按现有契约访问 Dealer 商品接口 | 其他企业数据、Admin 配置 |
| `ADMIN` | 首页草稿/已发布配置、完整商品管理字段 | 不得在公开响应中转发密码哈希、密钥或内部审计字段 |

前端根据角色显示入口只改善体验，不构成授权。所有 Admin 写入接口必须由 JWT Guard 和 Roles Guard 在服务端限制为 `ADMIN`。

## 3. 公开首页接口

### 3.1 `GET /api/v1/storefront/home`

- 权限：`PUBLIC`。
- 返回当前已发布的首页配置；不能根据 query 参数读取草稿或指定历史版本。
- 没有已发布配置时仍返回 HTTP 200，使用安全默认值：空的精选商品和分类数组、空 CTA，前端不得因空数据渲染白屏。
- 公开响应不得包含 `status`、`draft`、`updatedBy`、内部 ID 列表以外的后台字段、`dealerPrice`、`stock` 或 `reserved`。

建议响应结构：

```json
{
  "version": 1,
  "hero": {
    "title": "Move more. Play together.",
    "subtitle": "",
    "imageUrl": "/media/home-hero.jpg",
    "mobileImageUrl": null,
    "actions": [
      { "label": "Explore products", "href": "/products" }
    ]
  },
  "categories": [
    { "id": 1, "name": "Outdoor games", "slug": "outdoor-games" }
  ],
  "featuredProducts": [
    {
      "id": 1,
      "name": "Demo Set",
      "slug": "demo-set",
      "shortDescription": "",
      "price": 29.99,
      "ageMin": 3,
      "ageMax": 10,
      "playEnvironment": "outdoor",
      "features": [],
      "specifications": {},
      "category": null,
      "createdAt": "2026-09-07T00:00:00.000Z"
    }
  ],
  "dealerCta": {
    "label": "Become a dealer",
    "href": "/dealer/apply"
  }
}
```

约束：

1. `featuredProducts` 必须从当前 ACTIVE 且未软删除的商品中解析；已删除、草稿或归档商品自动过滤。
2. 精选商品沿用现有公开商品 DTO，禁止重新定义一套带有内部字段的商品对象。
3. `href` 只允许站内相对路径或经审查的 `https://` URL；后台保存时拒绝 `javascript:`、`data:` 等协议。
4. `actions` 最多 2 个；`categories` 和 `featuredProducts` 的数量上限由 DTO 固定，避免首页响应无限膨胀。
5. 图片 URL 只表达公开资源位置；本轮不返回私有文件的签名参数，也不把真实客户文件放入媒体目录。

## 4. Admin 首页配置接口

以下路由均为 `ADMIN`，响应沿用全局成功/失败外层结构。

### 4.1 `GET /api/v1/admin/storefront/home`

返回当前草稿和已发布版本的管理视图。管理字段可以包含 `status`、`updatedAt`、`updatedBy` 和 ID 引用，但不得包含密码哈希、JWT 密钥或无关用户字段。

### 4.2 `PUT /api/v1/admin/storefront/home`

保存首页草稿。请求只接受本契约定义的字段：

```json
{
  "hero": {
    "title": "Move more. Play together.",
    "subtitle": "",
    "imageUrl": "/media/home-hero.jpg",
    "mobileImageUrl": null,
    "actions": [
      { "label": "Explore products", "href": "/products" }
    ]
  },
  "categoryIds": [1],
  "featuredProductIds": [1],
  "dealerCta": {
    "label": "Become a dealer",
    "href": "/dealer/apply"
  }
}
```

校验要求：

- 标题、按钮文案、链接、图片字段执行 DTO 长度和协议校验；数组去重并限制数量。
- `categoryIds` 只能引用存在的分类；`featuredProductIds` 只能引用存在且未删除的商品。发布时再次过滤非 ACTIVE 商品。
- 草稿保存不改变公开首页；保存失败返回 400，不能留下半份配置。
- 未知字段由全局 `ValidationPipe` 拒绝，不能静默持久化。

### 4.3 `POST /api/v1/admin/storefront/home/publish`

发布当前草稿，使其成为 `GET /storefront/home` 的唯一数据源。发布前必须重新校验：

- Hero 至少有可读标题或安全默认标题。
- 所有 CTA 链接通过协议校验。
- 引用的商品和分类仍符合公开条件。
- 公开首页不会因为空集合或失效图片返回 500。

本轮不提供历史版本切换和定时发布；如草稿/发布需要版本号，版本号只用于并发和验收，不作为公开内容筛选参数。

## 5. 商品公开契约复用规则

P2 前端继续使用现有接口：

- `GET /api/v1/products`：公开商品列表，固定过滤 `ACTIVE` 且 `deletedAt = null`。
- `GET /api/v1/products/:slug`：公开商品详情和 ACTIVE SKU 列表。
- 公开商品不得出现 `dealerPrice`、`status`、`deletedAt`、`createdBy`、`stock`、`reserved` 等字段。
- `GET /api/v1/products` 的公开查询只接受已定义的 `page`、`limit`、`sort`、`categoryId`、`search`；不得通过 `status` 参数绕过公开过滤。
- SKU 的 `isPurchasable` 只能表达当前可购买状态。购物车和订单仍通过 `VariantsService.getPurchasableVariant` 重新读取价格和库存，不能信任浏览器传回的价格。

若商品公开 DTO 需要新增字段，成员 2 必须同时更新 Swagger、前端类型和本契约；成员 1 审查字段是否会扩大数据暴露面。

## 6. 统一错误与权限测试

| 场景 | 预期 |
| --- | --- |
| 匿名读取公开首页/商品 | 200；仅公开字段 |
| 未登录访问 Admin 首页接口 | 401 |
| `USER`、`DEALER` 访问 Admin 首页接口 | 403 |
| 非法链接协议、未知字段、数组超限 | 400 |
| 精选商品引用不存在 ID | 400 或 404，错误语义在 Swagger 中固定 |
| 草稿引用的商品随后被归档 | 发布时过滤；公开首页不出现 |
| 无已发布配置 | 200 安全默认值，不白屏、不泄露草稿 |
| 公共商品列表传入 `status=DRAFT` | 400 或忽略并固定 ACTIVE；行为需由测试锁定 |

成员 6 至少补充以下回归：公开首页草稿隔离、Admin 401/403、精选商品 ACTIVE 过滤、公开字段白名单、首页空状态、桌面/移动端首页加载和商品详情加购路径。

## 7. 实现顺序与合并门槛

1. 成员 1 先审查本契约和数据模型方案；涉及 Prisma 的实现必须提交 migration 与空库迁移记录。
2. 成员 2 先保证商品/分类查询和公开 DTO 稳定，再实现首页配置所依赖的展示数据。
3. 成员 5 实现 Admin 最小配置页，成员 4 在契约稳定后接入 `GET /storefront/home`；两者不得将 mock 作为最终数据源。
4. 成员 3 仅负责现有购物车、订单接口与页面联调回归，不在 P2 增加支付、税费、报价或 Dealer 交易功能。
5. PR 合并前运行后端 `lint`、`typecheck`、单元测试和构建；涉及前端时增加前端测试和生产构建；成员 6 运行独立测试库 API/E2E。
6. 任何公开字段、角色、路由、错误状态或 migration 变化必须在 PR 说明中标注本文件受影响章节。

## 8. 本轮明确不提供的接口

以下接口不应为了“先占位”而加入 P2：

- 支付会话、支付回调、退款、地址、配送、税费和优惠码。
- Dealer 价格表、MOQ、报价、企业成员、快速下单和发货。
- 通用 CMS、文章编辑、FAQ、下载中心、全站搜索和多语言内容管理。

这些能力进入后续 backlog，开始实现前需要单独完成数据、权限、外部写入和上线风险评审。
