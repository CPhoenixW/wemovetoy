# WEMOVE SPORTS 使用文档

本文说明如何在本机启动 P1 后端、初始化数据库、查看接口并完成基本认证验证。

## 1. 前置条件

- Docker Desktop 已安装并处于运行状态。
- 已安装 Node.js 和 npm。建议团队统一使用当前 LTS 版本。
- 本机 `5432` 端口未被其他 PostgreSQL 占用；如被占用，请修改根目录 `.env` 中的 `POSTGRES_PORT`。
- 本机 `3000` 端口未被其他服务占用；如被占用，请修改 `.env` 中的 `PORT`。

在项目根目录创建本地环境文件：

```bash
cp .env.example .env
```

该 `.env` 同时供 Docker Compose 与后端读取。首次启动前应至少替换 `JWT_SECRET`；不要上传 `.env`。

## 2. 首次安装与启动

在仓库根目录启动 PostgreSQL：

```bash
docker compose up -d
docker compose ps
```

确认 `postgres` 服务处于运行/健康状态后，安装并启动后端：

```bash
cd backend
npm install
npm run prisma:generate
npm run prisma:migrate
npm run prisma:seed
npm run start:dev
```

首次迁移会创建 `User` 表和 `USER`、`DEALER`、`ADMIN` 角色枚举。开发服务器默认读取 `.env` 的 `PORT=3000`；日志出现应用正在监听后即可访问接口。

日常拉取已有迁移后的启动步骤通常是：

```bash
docker compose up -d
cd backend
npm install
npm run prisma:generate
npm run prisma:migrate
npm run prisma:seed
npm run start:dev
```

`prisma:seed` 可重复执行，会按邮箱更新或创建开发种子账户。它适用于本地开发，不应用于生产环境。

## 3. 服务检查与 Swagger

以默认端口为例：

```bash
curl http://localhost:3000/api/v1/health
```

正常响应会被统一包装：

```json
{
  "success": true,
  "data": { "status": "ok" },
  "message": "success",
  "request_id": "..."
}
```

浏览器打开 `http://localhost:3000/api/docs` 可查看和调试 Swagger。使用受保护接口前，先通过登录接口获取 `accessToken`，点击 Swagger 的 **Authorize**，输入 `Bearer <accessToken>`。

## 4. 种子账户与认证流程

运行 `npm run prisma:seed` 后会创建下列开发账户：

| 角色 | 邮箱 | 默认密码 |
| --- | --- | --- |
| `USER` | `user@wemove.local` | `ChangeMe123!` |
| `DEALER` | `dealer@wemove.local` | `ChangeMe123!` |
| `ADMIN` | `admin@wemove.local` | `ChangeMe123!` |

种子密码可通过运行 seed 前设置 `SEED_DEFAULT_PASSWORD` 覆盖。它只用于本地开发；演示以外的环境必须改用安全密码。

注册普通用户：

```bash
curl -X POST http://localhost:3000/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"new-user@example.com","password":"ChangeMe123!","name":"New User"}'
```

登录并获取令牌：

```bash
curl -X POST http://localhost:3000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@wemove.local","password":"ChangeMe123!"}'
```

从响应的 `data.accessToken` 复制令牌后查询当前用户：

```bash
curl http://localhost:3000/api/v1/auth/me \
  -H 'Authorization: Bearer <accessToken>'
```

缺少、过期或无效令牌会返回 401；登录后访问角色不匹配的接口会返回 403。所有成功和失败响应都包含 `request_id`，反馈问题时请一并提供它。

可用种子账户进一步验证角色权限：使用 `admin@wemove.local` 的令牌请求 `GET /api/v1/admin/ping` 应返回 200；使用 `dealer@wemove.local` 的令牌请求 `GET /api/v1/dealer/ping` 应返回 200；普通 `USER` 请求这两个地址应返回 403。未带令牌请求它们应返回 401。这两个接口仅用于验证 P1 权限基础设施，不代表后台或经销商业务已经实现。

## 5. 常用命令

所有以下 npm 命令均在 `backend/` 内执行：

| 命令 | 用途 |
| --- | --- |
| `npm run start:dev` | 监听源代码变更并启动开发服务器 |
| `npm run build` | 构建 TypeScript 项目 |
| `npm run lint` | 运行 ESLint |
| `npm test` | 运行 Jest 测试 |
| `npm run prisma:generate` | 生成 Prisma Client |
| `npm run prisma:migrate -- --name <名称>` | 根据 schema 创建并应用开发迁移 |
| `npm run prisma:deploy` | 仅应用已提交迁移 |
| `npm run prisma:seed` | 写入/更新本地种子账户 |

停止数据库服务：

```bash
docker compose down
```

该命令保留 Docker 数据卷。清除数据卷会永久删除本地数据库，应仅在确认不需要现有本地数据后按团队约定操作。

## 6. 常见问题

**Docker 服务未启动**：执行 `docker compose ps` 检查状态，确认 Docker Desktop 已启动后再执行 `docker compose up -d`。

**端口已占用**：修改根目录 `.env` 中的 `POSTGRES_PORT` 或 `PORT`，重新启动对应服务。修改数据库端口后，也要保持 `DATABASE_URL` 与之相同。

**Prisma 无法连接数据库**：确认 PostgreSQL 容器已运行，检查 `.env` 的 `DATABASE_URL` 与 `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_PORT` 是否一致，再重新执行迁移。

**拉取代码后类型或数据库不一致**：在 `backend/` 运行 `npm install`、`npm run prisma:generate`、`npm run prisma:migrate`，然后执行测试与启动检查。

**接口响应 401/403**：401 表示未携带有效 JWT；403 表示令牌对应的角色没有该接口权限。先使用正确种子账户重新登录，并检查 `Authorization` 头是 `Bearer <accessToken>` 格式。
