## 6. PR 触发规则与交付证据

| PR 类型 | 成员 6 最小动作 |
| --- | --- |
| 商品字段、筛选或公开 DTO | 执行 P2-A06、A07、A11～A13，并完整回归 P2-T01～T05 |
| 首页配置 API、权限或 migration | 空库迁移；执行 P2-A01～A10；核对 Swagger、前端类型和权限证据 |
| 官网首页/列表/详情 | 执行 P2-B01、B03～B07 与 P2-R01～R06 |
| Admin 配置页 | 执行 P2-B02、B07、B08 与 P2-R01、R03～R05 |
| 购物车/订单改动 | 完整 API E2E 和 P2-T01～T06，不接受仅测成功路径 |
| 跨模块或发布候选 | 独立测试库迁移/seed、前后端 lint/test/build、API E2E、浏览器 E2E、移动端/键盘抽检和发布清单 |

每次验收记录必须包含：目标 PR/commit、测试日期、数据库名称、执行命令、通过/失败数量、失败复现步骤、截图或 CI 链接、是否建议合并。只有代码已经存在并在指定 commit 实测后，才能把状态改为“通过”。
