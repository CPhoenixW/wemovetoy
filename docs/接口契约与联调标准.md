# WEMOVE P1 接口契约与联调标准

本文由成员 1 维护，是商品、SKU、购物车、订单和前端联调的唯一目标契约。它解决的是“下一轮应实现什么”，不是对当前实现状态的宣传。

## 1. 生效范围与状态

- 生效分支：`develop`。
- 目标版本：P1 交易联调版。
- 当前事实：认证、商品、购物车、订单和经销商路由已存在；公开商品字段边界、按 `variantId` 的可售 SKU 查询、真实定价、真实库存校验和 Admin 订单列表尚未完成。
- 本文中的“必须”表示对应负责人提交 PR 前必须达到的条件。未达到时，调用方可以完成页面结构，但不能把 mock 当作可联调功能，也不能合入业务页面。

本文不会新增数据库字段或改变现有路由。任何与本文不一致的代码由模块负责人在自己的 PR 中修正，并更新 Swagger、测试和前端类型。

## 2. 全局约定

### 2.1 地址、认证与角色

所有业务路由统一使用 `/api/v1` 前缀。Nest 全局前缀已经负责此工作，Controller 不得再写 `@Controller("api/v1")`，否则会产生 `/api/v1/api/v1/...`。

受保护接口使用：

```http
Authorization: Bearer <accessToken>
```

角色含义：

| 标记 | 可调用者 | 说明 |
| --- | --- | --- |
| `PUBLIC` | 未登录或已登录用户 | 只能读取公开商品字段 |
| `AUTH` | 任意有效 JWT | 用户、Dealer 和 Admin 均可调用；价格层级由服务端身份决定 |
| `DEALER` | `DEALER` JWT | 可读取经销商价格和 Dealer 业务数据 |
| `ADMIN` | `ADMIN` JWT | 可管理商品、审核经销商、查看全部订单 |

前端显示或浏览器中的角色信息不构成授权。后端必须使用 JWT Guard 和 Roles Guard 决定访问权限。

### 2.2 成功与失败响应

成功响应固定为：

```json
{
  "success": true,
  "data": {},
  "message": "success",
  "request_id": "..."
}
```

失败响应固定为：

```json
{
  "success": false,
  "message": "...",
  "request_id": "..."
}
```

当前公共异常过滤器尚未输出 JSON `code` 字段。因此本文的业务错误码用于 Swagger 描述、PR 说明和测试名称；客户端当前以 HTTP 状态和 `message` 判断错误。成员不得私自添加另一种错误外层结构。若后续需要机器可读的 `code` 字段，由成员 1 单独修改公共异常规范并统一迁移。

| HTTP 状态 | 业务错误码 | 使用场景 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | DTO 校验失败、数量小于 1、非法查询参数 |
| 400 | `VARIANT_NOT_PURCHASABLE` | 商品或 SKU 未上架、已删除或不可购买 |
| 400 | `INSUFFICIENT_STOCK` | 可售库存小于本次或累计请求数量 |
| 400 | `ORDER_EMPTY_CART` | 从空购物车创建订单 |
| 400 | `ORDER_STATUS_TRANSITION_INVALID` | 不符合订单状态流转 |
| 401 | `UNAUTHORIZED` | 缺少、过期或无效 JWT |
| 403 | `FORBIDDEN` | 已登录但角色或数据归属不符合要求 |
| 404 | `PRODUCT_NOT_FOUND` | 不存在、已删除或不对当前调用方公开的商品 |
| 404 | `VARIANT_NOT_FOUND` | 不存在的 `variantId` 或 SKU |
| 404 | `CART_ITEM_NOT_FOUND` / `ORDER_NOT_FOUND` | 不存在或不属于当前用户的购物车项、订单 |
| 409 | `PRODUCT_SLUG_CONFLICT` | 创建或修改商品时 slug 重复 |
| 500 | `INTERNAL_ERROR` | 未预期错误；不得以外键错误代替 400/404 |

金额字段使用 JSON number，保留两位小数语义；数据库 `Decimal` 必须在 Service 层转换。所有时间使用 ISO 8601 字符串。分页响应固定含 `items`、`total`、`page`、`pageSize`、`totalPages`。

## 3. 商品与 SKU 契约（成员 2）

### 3.1 公开商品

#### `GET /api/v1/products`

| 项目 | 约定 |
| --- | --- |
| 权限 | `PUBLIC` |
| 查询 | `page`，`limit`（1-100），`sort`（`newest`、`price_asc`、`price_desc`、`name_asc`、`name_desc`），`categoryId`，`search` |
| 服务端过滤 | 固定 `Product.status = ACTIVE` 且 `deletedAt = null` |
| 禁止查询 | 公开接口不接受 `status=DRAFT`、`status=ARCHIVED` 等状态筛选；未知字段由 ValidationPipe 返回 400 |
| 成功 | 200，返回公开商品分页数据 |

`items` 中的公开商品字段只允许：

```json
{
  "id": 1,
  "name": "50块标准款套装",
  "slug": "50-piece-std-set",
  "shortDescription": "...",
  "price": 29.99,
  "ageMin": 3,
  "ageMax": 10,
  "playEnvironment": "indoor",
  "features": ["..."],
  "specifications": { "material": "ABS塑料" },
  "category": { "id": 1, "name": "积木玩具", "slug": "building-blocks" },
  "createdAt": "2026-09-06T00:00:00.000Z"
}
```

公开商品禁止出现：`dealerPrice`、`status`、`deletedAt`、`createdBy`、内部库存、`reserved` 和任何后台审核字段。

#### `GET /api/v1/products/:slug`

| 项目 | 约定 |
| --- | --- |
| 权限 | `PUBLIC` |
| 服务端过滤 | 仅返回 ACTIVE 且未删除商品；不存在与非公开商品均返回 404 `PRODUCT_NOT_FOUND` |
| 成功 | 200，返回上述公开商品字段以及 `description`、公开 SKU 列表 |

公开 SKU 只允许返回：

```json
{
  "id": 101,
  "sku": "BLOCK-50-STD",
  "name": "标准款",
  "options": { "color": "mixed" },
  "price": 29.99,
  "isPurchasable": true
}
```

`dealerPrice`、`stock`、`reserved`、SKU 内部状态不得出现在公开详情中。官网前端由成员 4 只依赖此 DTO，不得保留匿名 `dealerPrice` 类型或自行传递 `status` 查询。

### 3.2 后台商品

| 路由 | 权限 | 目的 |
| --- | --- | --- |
| `GET /api/v1/admin/products` | `ADMIN` | 后台分页、状态、分类、搜索查询；`status` 在此接口可用 |
| `GET /api/v1/admin/products/:id` | `ADMIN` | 查询单件商品及后台字段、SKU、库存 |
| `POST /api/v1/admin/products` | `ADMIN` | 创建草稿商品 |
| `PATCH /api/v1/admin/products/:id` | `ADMIN` | 修改商品 |
| `POST /api/v1/admin/products/:id/publish` | `ADMIN` | 发布商品 |
| `DELETE /api/v1/admin/products/:id` | `ADMIN` | 软删除商品 |

后台 DTO 可以包含 `status`、`dealerPrice`、SKU `stock`、`reserved`，但不得复用公开 DTO。创建、修改必须执行 DTO 校验；slug 冲突返回 409 `PRODUCT_SLUG_CONFLICT`。

### 3.3 Dealer 商品

#### `GET /api/v1/dealer/products`

| 项目 | 约定 |
| --- | --- |
| 权限 | `DEALER` |
| 查询 | 与公开商品相同的分页、排序、分类、搜索参数 |
| 服务端过滤 | 固定 ACTIVE、未删除、可供 Dealer 浏览的商品 |
| 成功 | 200，分页返回 Dealer DTO |

Dealer 商品 DTO 使用明确的价格含义：

```json
{
  "id": 1,
  "name": "50块标准款套装",
  "slug": "50-piece-std-set",
  "retailPrice": 29.99,
  "dealerPrice": 22.49,
  "variants": [
    {
      "id": 101,
      "sku": "BLOCK-50-STD",
      "name": "标准款",
      "unitPrice": 22.49,
      "availableStock": 20,
      "isPurchasable": true
    }
  ]
}
```

`unitPrice` 是当前 Dealer 下单时的展示价格；购物车和订单仍必须通过 SKU 服务在服务端重新计算，不能信任浏览器传回的数值。普通 `USER` 调用本接口返回 403 `FORBIDDEN`，未登录返回 401。

### 3.4 SKU 查询接口

SKU 不是 Product ID；所有 SKU 查询路径参数均为唯一的 `sku` 字符串。详情页的公开 SKU 列表是匿名展示来源；此处的单 SKU 查询仅供已登录用户在加入购物车前刷新当前可售性，交易模块仍必须使用下一节的内部服务。

| 路由 | 权限 | 成功 | 错误 |
| --- | --- | --- | --- |
| `GET /api/v1/variants/:sku` | `AUTH` | 200，当前身份可见的 SKU | 400、401、404 |
| `POST /api/v1/variants/batch` | `AUTH` | 200，`{ "items": [...] }`；请求为 `{ "skus": ["..."] }`，最多 100 个且去重 | 400、401、404 |

普通用户返回：

```json
{
  "id": 101,
  "sku": "BLOCK-50-STD",
  "productId": 1,
  "productName": "50块标准款套装",
  "name": "标准款",
  "options": { "color": "mixed" },
  "unitPrice": 29.99,
  "isPurchasable": true
}
```

`DEALER` 返回相同字段，并额外返回 `availableStock`；其 `unitPrice` 是 Dealer 当前价格。`USER`、`ADMIN` 均使用零售价。该接口不得返回 `dealerPrice`、`stock`、`reserved`、`status`、条码或 SKU 管理字段。不存在 SKU 返回 404 `VARIANT_NOT_FOUND`；商品/SKU 不可售返回 400 `VARIANT_NOT_PURCHASABLE`；批量请求中任一 SKU 不存在或不可售时整个请求失败，不得静默漏项。

`POST /api/v1/variants/check-stock` 不是对前端开放的长期接口。库存校验由购物车、下单时的 Service 负责；成员 2 应删除该 Controller 路由或改成仅限内部调用，防止客户端绕过可售性和价格规则探测库存。

### 3.5 模块内 SKU 查询服务

购物车与订单不得通过 Controller 调用 Controller，也不得自行查询 `Variant` 表。成员 2 必须从 `ProductsModule` 导出以下稳定 Service 契约：

```ts
type PriceAudience = "RETAIL" | "DEALER";

interface PurchasableVariant {
  variantId: number;
  sku: string;
  productId: number;
  productName: string;
  variantName: string;
  unitPrice: Prisma.Decimal;
  availableStock: number;
  isPurchasable: boolean;
}

getPurchasableVariant(
  variantId: number,
  audience: PriceAudience,
): Promise<PurchasableVariant>;
```

实现规则：

- 不存在 `variantId` 时抛出 404 `VARIANT_NOT_FOUND`。
- 商品必须 ACTIVE、未删除；SKU 必须 ACTIVE；否则抛出 400 `VARIANT_NOT_PURCHASABLE`。
- `availableStock = stock - reserved`，不得为负数。
- `RETAIL` 使用 SKU 零售价；`DEALER` 优先使用 SKU Dealer 价，缺失时回退零售价。
- 服务返回真实商品名和 SKU 名称，订单不得再写入 `Variant #<id>`。

现有按 `sku` 的 Controller 不是购物车、订单的正式依赖；后续实现不得保留双重 `/api/v1` 前缀，也不得向匿名用户返回 Dealer 价格。

## 4. 购物车契约（成员 3）

所有购物车路由为 `AUTH`。实际价格层级由 JWT 角色决定：`DEALER` 使用 Dealer 价格，其余角色使用零售价；客户端永远不提交 `unitPrice`。

### 4.1 购物车数据

```json
{
  "id": 1,
  "items": [
    {
      "id": 10,
      "variantId": 101,
      "sku": "BLOCK-50-STD",
      "productName": "50块标准款套装",
      "variantName": "标准款",
      "quantity": 2,
      "unitPrice": 29.99,
      "subtotal": 59.98,
      "availableStock": 20,
      "isPurchasable": true
    }
  ],
  "itemCount": 2,
  "totalAmount": 59.98,
  "updatedAt": "2026-09-06T00:00:00.000Z"
}
```

`id` 是购物车项 ID；更新和删除使用它。`variantId` 是 SKU ID；加购只能使用它，不能使用 Product ID。

### 4.2 路由

| 路由 | 权限 | 请求 | 成功 | 错误 |
| --- | --- | --- | --- | --- |
| `GET /api/v1/cart` | `AUTH` | 无 | 200，购物车数据 | 401 |
| `POST /api/v1/cart/items` | `AUTH` | `{ "variantId": 101, "quantity": 2 }` | 201，更新后的购物车项 | 400、401、404 |
| `PATCH /api/v1/cart/items/:id` | `AUTH` | `{ "quantity": 3 }` | 200，更新后的购物车项 | 400、401、404 |
| `DELETE /api/v1/cart/items/:id` | `AUTH` | 无 | 200 或 204 | 401、404 |
| `DELETE /api/v1/cart` | `AUTH` | 无 | 200 或 204 | 401 |

加购与改数量的固定规则：

1. 通过 `getPurchasableVariant` 查询真实 SKU。
2. 加购已存在项时检查 `现有数量 + 请求数量 <= availableStock`。
3. 改数量时检查 `请求数量 <= availableStock`。
4. 库存不足返回 400 `INSUFFICIENT_STOCK`；不可购买返回 400 `VARIANT_NOT_PURCHASABLE`；不存在 SKU 返回 404。
5. 返回数据中的价格、名称、金额全部由服务端生成。

## 5. 订单与后台订单契约（成员 3）

### 5.1 用户订单

| 路由 | 权限 | 请求或查询 | 成功 | 错误 |
| --- | --- | --- | --- | --- |
| `POST /api/v1/orders` | `AUTH` | `shippingName`、`shippingPhone`、`shippingAddress`、`remark` 均可选，且不包含价格或商品项 | 201，完整订单快照 | 400、401、404 |
| `GET /api/v1/orders` | `AUTH` | `page`、`pageSize` | 200，仅当前用户订单分页 | 401 |
| `GET /api/v1/orders/:id` | `AUTH` | 无 | 200，订单所有者可读；Admin 可以读单件 | 401、403、404 |
| `PATCH /api/v1/orders/:id/cancel` | `AUTH` | 无 | 200，取消当前用户待处理订单 | 400、401、403、404 |

创建订单时，订单服务必须重新逐项调用 SKU 服务，不得重用购物车中可能过期的价格、库存或名称。订单创建与清空购物车必须在同一数据库事务内完成。

订单快照至少包含：

```json
{
  "id": 5001,
  "orderNumber": "WM2026090612345678",
  "status": "PENDING",
  "totalAmount": 59.98,
  "shippingName": "张三",
  "createdAt": "2026-09-06T00:00:00.000Z",
  "items": [
    {
      "id": 1,
      "variantId": 101,
      "sku": "BLOCK-50-STD",
      "productName": "50块标准款套装",
      "variantName": "标准款",
      "quantity": 2,
      "unitPrice": 29.99,
      "subtotal": 59.98
    }
  ]
}
```

P1 不做支付、真实库存扣减和预占。下单前二次校验当前库存是必须项；订单生成后保存不可变价格和名称快照。

订单状态流转固定为：

```text
PENDING -> PAID -> SHIPPED -> DELIVERED -> COMPLETED
PENDING -> CANCELLED
PAID -> CANCELLED
```

任何未列出的流转返回 400 `ORDER_STATUS_TRANSITION_INVALID`。

### 5.2 Admin 订单列表

成员 3 必须新增独立后台路由，前端 Admin 不得使用“当前用户订单”冒充全量订单：

| 路由 | 权限 | 查询 | 成功 |
| --- | --- | --- | --- |
| `GET /api/v1/admin/orders` | `ADMIN` | `page`、`pageSize`、`status`、`search` | 200，订单分页 |
| `GET /api/v1/admin/orders/:id` | `ADMIN` | 无 | 200，完整订单和快照 |
| `PATCH /api/v1/admin/orders/:id/status` | `ADMIN` | `{ "status": "PAID" }` | 200，更新后的订单 |

后台列表每项至少包含：

```json
{
  "id": 5001,
  "orderNumber": "WM2026090612345678",
  "status": "PENDING",
  "totalAmount": 59.98,
  "itemCount": 2,
  "customer": {
    "id": 1,
    "email": "user@example.com",
    "name": "Demo User",
    "role": "USER"
  },
  "dealerCompany": null,
  "createdAt": "2026-09-06T00:00:00.000Z"
}
```

`search` 只匹配订单号、客户邮箱、客户名称和公司名称；不得将密码哈希或无关用户字段放入订单响应。未登录返回 401，非 Admin 返回 403。

## 7. 当前禁止项

- 不得通过公开 `/products` 获取 Dealer 价格或草稿商品。
- 不得以 Product ID 替代 `variantId` 加购。
- 不得在 Cart 或 Orders 中保留 0 元、无限库存或 `Variant #id` 占位实现。
- 不得把 mock、本地 `useState` 删除或 `alert` 结算视为真实业务完成。
- 不得只因 CI 通过就合并；必须满足对应路由、权限、异常和跨模块验收条件。
